Writing and checking a function

A def statement defines a function; the indented body runs when it is called. Arguments supply inputs; return sends a result back to the caller. print only displays something. A local name belongs to that call. A docstring is a quoted description at the start. Test ordinary, zero and negative inputs with expected results chosen independently. A test is evidence about those cases, not a proof for every real input.

Worked example

Read the example one line at a time. Identify the inputs, predict the displayed quantities, then type and run it in your selected notebook kernel. Library calls are explained in this section; preserve your own prediction before execution.

Type, predict, run

def corrected(reading):
    """Return the supplied calibration 2x + 3."""
    result = 2 * reading + 3
    return result

assert corrected(0) == 3
assert corrected(-2) == -1
print(corrected(4))

SECTION 2 · ABOUT 220 MINUTES

Work, explain and check

Verification should target a possible failure. Check an ordinary input, a boundary or excluded input where relevant, and a result you can obtain independently by hand. Do not execute an unknown proposed program merely because it is described as helpful.

Worked example

For f(x)=2x+3 and g(x)=x², f(g(2))=11 while g(f(2))=49. The inverse of f is (y−3)/2. The square function has no inverse on all real numbers: ±2 both give 4. Restricting to x≥0 gives inverse √y, with y≥0.

Work it through

Show intermediate steps and give units or restrictions where relevant. For code, record a prediction before running.

  1. For h(x)=(x−2)²+1, identify its vertex and minimum.
  2. Find the inverse of y=3x−6.
  3. State domain and range of |x| on the real line; explain why it is not one-to-one.
Feedback and worked answers
  1. Vertex (2,1); minimum 1.
  2. x=(y+6)/3.
  3. Domain all real numbers, range [0,∞); opposite non-zero inputs share an output.
