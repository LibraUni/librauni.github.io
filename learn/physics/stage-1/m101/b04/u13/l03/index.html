A reproducible synthesis

We now have enough analytical structure to make a computer calculation informative. The aim is to connect small functions whose meanings are clear, then test the chain at points where a mistake could change the answer.

Allow 45 minutes for reading and worked reasoning, 40 for written planning, 35 for feedback and three hours for the investigation. Use the notebook or plain Python companion. The notebook also contains Lesson 2's separate one-hour tangent exploration. Start from a fresh kernel and run the definitions in order.

13.9 Build a transparent calculation

Begin by writing what each function accepts and returns. Our numerical convention is seconds for time, metres for position and metres per second for velocity. A two-entry tuple always puts the east component first. These conventions allow short code, but they belong in the report because the program does not attach physical units to its numbers.

The position function returns (ut,wt−kt2); the velocity function returns (u,w−2kt). Their default coefficients describe the baseline journey. Changing a coefficient defines a controlled variant of the supplied model, still on 0–4 s. The companion checks finite inputs and that time lies in this domain. It allows signed coefficients for mathematical investigations; interpretation of any variant must follow its actual components.

The channel functions should have one responsibility each:

def encode(vector):
    x, y = vector
    return (x+y, x-y)


def decode(channels):
    p, q = channels
    return ((p+q)/2, (p-q)/2)

Next reuse the scalar trapezoidal routine. If n is the number of panels, there are n+1 nodes. Endpoint values receive half weight; the interior loop includes indices 1 through n−1. The width multiplies the whole weighted sum:

from math import isfinite


def trapezoid(f, a, b, n):
    if isinstance(n, bool) or not isinstance(n, int) or n < 1:
        raise ValueError("n must be a positive integer")
    if not (isfinite(a) and isfinite(b)):
        raise ValueError("Finite integration bounds required")
    h = (b-a)/n
    total = 0.5*(f(a)+f(b))
    for j in range(1, n):
        total += f(a+j*h)
    return h*total

The routine integrates one numerical function. We call it separately on each velocity component for displacement, then on speed for distance. The short lambda expressions in the companion name a one-input function; for example, lambda t: velocity(t)[0] returns the east component at time t. An ordinary named function with a return statement would do the same job.

Activity 13.9 · Trace one panel before running many

Trace a one-panel integral of the east velocity from 0 to 4 s. Give the node times, endpoint weights, width, weighted sum and final units. Then trace the north component and explain why this coarse rule is exact for both components.

Discussion of Activity 13.9

The node times are 0 and 4 s, width 4 s, and both endpoint weights are one half. East values are 2 and 2 m/s, so the weighted sum is 2 m/s and the integral is 8 m. North values are 4 and −4 m/s, giving zero. A trapezoid integrates any linear function exactly; both component rates are linear or constant. This fact says nothing about exactness for their nonlinear magnitude.

13.10 Check the vector result independently

The strongest readily available displacement benchmark comes from the position endpoints. Its calculation avoids the quadrature loop. If a component integral disagrees with that benchmark, first trace the scalar integration routine with a constant and a shifted linear function, as in Unit 12. Then inspect the chosen component and units.

A check must also be capable of exposing the suspected mistake. Suppose someone integrates channel rates and calls their magnitude the endpoint separation. The baseline channel changes are (8,8) m, with magnitude 82 m. Decoding them first gives (8,0) m and separation 8 m. The calibration's length scaling predicts precisely this discrepancy.

Example 13.7 · Repair a convincing wrong distance

A program evaluates the speed of the channel-rate vector, integrates it and reports about 16.73 m. It passes a non-negativity check and exceeds the endpoint separation. Find a check that reveals the error.

For any physical velocity (vx,vy), the channel rates are (vx+vy,vx−vy). The sum of their squares is 2(vx2+vy2). Thus channel-rate magnitude is 2 times physical speed at every time. The incorrect integral has the same factor. Divide neither blindly nor merely to match a target: repair the calculation by decoding rates before taking their magnitude, then verify the exact scaling relation on several vectors.

An additional exact benchmark sets k=0. The physical velocity is then the constant (2,4) m/s, so four seconds of travel covers 420 m. Every positive panel count must recover this value to rounding accuracy. The wrong channel calculation instead gives 2 times that value, revealing the error even though no refinement is involved.

The companion tests both coordinate directions through encode and decode, checks scalar quadrature independently and compares the integrated velocity with endpoint differences. The zero vector alone would miss several matrix mistakes, so it cannot replace the two coordinate-direction tests.

Activity 13.10 · Predict and test a defect

In a temporary copy, remove the factor one half from decode. Predict the effect on recovered positions, velocities and distance. Test a nonzero coordinate vector, restore the factor and rerun from the top. Explain which checks would still pass if the faulty decoder were used consistently on both sides of a comparison.

Discussion of Activity 13.10

Recovered vectors double, so their magnitudes and accumulated distances double. A nonzero coordinate test fails immediately. Comparing two calculations that both decode with the same faulty routine can still give agreement, and the zero input still maps to zero. A hand-derived physical endpoint benchmark and the direct constant-velocity distance expose the shared factor. Restore the original routine before continuing.

First hold the model fixed and vary panel count. The baseline outputs below were calculated with the scalar rule applied to speed. Displacement is (8,0) m at every listed resolution because its component integrands are linear.

The successive differences are approximately divided by four. This resembles the behaviour in Unit 11, but the speed is not a quadratic polynomial, so the exact quadratic error formula from Unit 12 does not apply. The table supports a stable estimate near 11.832 m. A requirement for a certified error smaller than a specified tolerance would need a justified bound or additional analysis.

We can nevertheless explain the direction of these estimates. Write the numerical speed as s(t)=4+(4−2t)2. Ordinary differentiation gives

s″(t)=16[4+(4−2t)2]3/2>0.

The speed curve is convex: its chords lie above it. Each trapezoidal panel therefore overestimates its area, and inserting panel midpoints lowers the estimate. This geometric argument establishes the side of the error; the refinement table indicates its shrinking scale.

Now keep a sufficiently fine resolution fixed and change a model input. For example, varying w changes the initial northward velocity. The endpoint north coordinate is 4w−16k, so a change δw changes the north displacement by exactly 4δw. This relation provides an analytical sensitivity check that is independent of the loop. Distance responds differently because the magnitude operation is nonlinear.

Activity 13.11 · The three-hour investigation

Use about 35 minutes to trace functions and run independent baseline checks, 45 minutes to reproduce the refinement table and diagnose the channel-rate mistake, 45 minutes to investigate input sensitivity, and 55 minutes for a clean rerun and short report.

  1. Predict displacement, endpoint separation and the four-panel distance before running. Compare both integrated components with endpoint differences.
  2. Run the six listed resolutions. Record successive distance differences. State what evidence supports your reported digits.
  3. Set k=0 and compare with constant-velocity distance for panel counts 1, 4 and 16. Test zero time interval in the scalar integrator separately.
  4. Restore k=1. Compare w=3.8,4.0,4.2 m/s at 128 and 256 panels. Predict the north-displacement changes first. Separate the effect of changing w from the effect of refinement.
  5. Restart and run all cells. Save your explanation of one successful check, one failed check and the limits of the conclusion.
Discussion and criteria for Activity 13.11

The displacement predictions are (8,−0.8), (8,0) and (8,0.8) m for the three w values. Their endpoint separations are equal for the two outer cases. Their distances are also equal: under t↦4−t, replacing w by 8−w reverses the north velocity's sign at corresponding times, leaving speed unchanged. This is a useful symmetry check. At 128 panels their distances are approximately 11.84972 m, compared with 11.83183 m at baseline. Refining each case should change it much less than the roughly 0.018 m input effect.

A strong report distinguishes exact endpoint and constant-velocity checks from numerical refinement evidence, labels all units and inputs, and explains the symmetry or another independently derived check. If a result fails, record the first check that failed and the repaired step. Re-running without explaining the failure leaves the mathematical question unresolved.

13.12 Write a reproducible account

A reader should be able to reconstruct the question without opening your notebook first. State the supplied position model, interval, coefficients, axes and numerical units. Then identify the outputs: vector displacement, endpoint separation and travelled distance. Name which operations produced each one. This makes the report a mathematical explanation with code evidence, rather than a list of printed numbers.

Example 13.8 · Match the claim to the evidence

A suitable baseline conclusion is: “For the supplied planar model on 0–4 s, integrating each velocity component gives displacement (8,0) m, agreeing with direct endpoint subtraction. Trapezoidal integration of physical speed gives 11.831834 m with 128 panels; the change from 64 panels is 0.000873 m. The positive second derivative explains the overestimate. Constant-velocity and scalar-rule benchmarks pass. I report distance as approximately 11.832 m, with refinement evidence rather than a proved error certificate.”

The statement identifies exactly what was checked. A further claim about the real drifter would require measured positions, their errors and evidence that the model describes them. More panels cannot supply that evidence.

Keep the notebook's parameters together and restore the stated baseline before the final run. Retain full numerical values in calculations and round only the displayed output. If you used assistance to write or repair code, state what was assisted and explain the relevant functions and checks yourself. The formative investigation is a place to develop that explanation.

Activity 13.12 · Audit a report

A report says, “All values agree, so the motion is accurate to eight decimal places.” Replace it with two or three sentences that distinguish analytical checks, numerical evidence and model validity. Include one specific number from your run and one useful next step.

Sample approach

“Integrated displacement agrees with the exact endpoint difference for the supplied model. With 128 panels the distance estimate is 11.83183402 m, differing from the 64-panel result by about 0.00087347 m; this does not establish eight-decimal-place accuracy. I would refine again or derive an error bound for a numerical tolerance, and compare with position observations if the question concerns real motion.” Other wording is appropriate if it preserves the quantity, evidence and next test.

We have now connected matrix decoding, differentiation, accumulation and checking in one reproducible argument. The final lesson changes the interpretation of the components. That will test whether the connections remain usable when the familiar picture of a moving point is removed.
