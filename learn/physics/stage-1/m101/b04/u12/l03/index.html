Diagnosing and repairing a calculation

The previous lessons separated the question, its inputs and the method used to calculate an answer. We can now use those distinctions to investigate a program. The aim is to find a defect, explain why it matters and design evidence that the repair addresses it.

Allow 70 minutes for explanation and worked reasoning, 60 minutes for written traces and predictions, 30 minutes for feedback, and two hours for Activities 12.11–12.12. Reserve the remaining 20 minutes for feedback on the closing exercises. Use the downloadable notebook as a record of predictions, changes and checks.

12.9 Separate sources of disagreement

Imagine that the pump calculation and a measured delivered volume disagree. There are several places to look. The supplied rate formula may not describe the actual pump; the coefficients may be uncertain; the trapezoidal approximation may be too coarse; or the program may implement the wrong sum. Finite-precision arithmetic adds another possible discrepancy. The observation alone does not identify which cause dominates.

Hold some parts of the investigation fixed while testing others. Compare a numerical rule with an exact integral for the same formula and inputs to investigate the calculation. Vary the coefficients within stated ranges to investigate input sensitivity. Compare the formula with observations to investigate the model. Each comparison needs its own reference.

It is helpful to draw the chain explicitly:

A model discrepancy can persist when numerical error tends to zero. Conversely, a good physical model can be used badly by an inaccurate calculation. In this unit we use implementation error for a mismatch between the intended algorithm and the written code. Ordinary floating-point rounding can occur even when the implementation faithfully expresses the algorithm.

Activity 12.9 · Which change addresses which cause?

For each action, name the issue it can address: (a) double the panel count; (b) correct range(n) to the intended interior-node range; (c) measure the pump's rate again; (d) keep more digits until the final display. Explain why none of these actions replaces all the others.

Discussion of Activity 12.9

(a) Tests and often reduces quadrature error, subject to model features and arithmetic. (b) Repairs sample counting if the original range was wrong. (c) Provides evidence about inputs or the rate model. (d) Avoids deliberate premature rounding, although machine arithmetic remains finite. They intervene at different stages; a correct loop cannot establish a measured coefficient, and a better measurement cannot correct a wrong loop.

12.10 Inspect a flawed check

The following code is deliberately flawed. Its author intended to approximate ∫uvf(t)dt by n equal trapezoidal panels and to check convergence by doubling n. Read it before running it.

# Deliberately flawed: diagnose before using.
def suspect(f, u, v, n):
    h = (v-u)/n
    total = (f(u) + f(v))/2
    for i in range(n):
        total += f(i*h)
    return round(h*total, 2)

q1 = suspect(lambda t: 3-t*t/4, 0, 3, 100)
q2 = suspect(lambda t: 3-t*t/4, 0, 3, 200)
print("validated:", q1-q2 < 0.1)

Begin with the mathematical formula. The endpoint average already contributes half of each endpoint, and the remaining sum must include only the n−1 interior nodes. The required positions are u+ih, with i=1,…,n−1. The loop shown includes i=0, and its positions omit the offset u. Those are separate defects. A test on an interval beginning at zero can expose the extra sample, but cannot expose the missing offset.

Example 12.7 · Trace one panel

Take f(t)=t, u=1, v=3, n=1. The exact integral is 4; the trapezoidal rule should also give 4 because the function is linear.

The code sets h=2, starts with (1+3)/2=2, and then adds f(0)=0. Multiplying by 2 happens to give 4. This test passes despite both loop defects. For the constant function f(t)=2 on the same interval, the code starts with 2, adds another 2 and returns 8, whereas the integral is 4.

Repairing only the loop range gives no interior terms when n=1, so the missing offset is still hidden. With two panels and f(t)=t, the interior point should be 2. Omitting the offset samples 1 instead and returns 1(2+1)=3, again instead of 4. A small set of chosen tests reveals more than repeatedly trying one familiar input.

Now inspect the validation statement. It tests a signed difference. If the first answer is much smaller than the second, their difference is negative and automatically less than 0.1. Taking the absolute value repairs that logic. It still only compares two outputs, so its interpretation depends on independent benchmarks and on the function's behaviour.

Rounding inside the function loses information before comparison. Return the unrounded result and format it only for display. Finally, the routine needs a defined input contract: a positive integer panel count, finite bounds and a function finite at every sampled node. Such guards catch invalid operations; they do not establish continuity between samples or physical validity.

Activity 12.10 · A false pass

A test compares q1=4.1 and q2=6.8 using q1-q2 < 0.1. What does it return? Rewrite the test to compare absolute discrepancy, and explain what even the corrected result would not establish.

Discussion of Activity 12.10

The signed difference is −2.7, so the test returns True. Use abs(q1-q2) < 0.1, which returns False. Passing the corrected comparison would establish proximity of these outputs, not accuracy relative to an exact integral, nor validity of the supplied model.

12.11 Test a repair independently

Before changing code, write the expected results of a few tests on paper. Include a constant function, a nonconstant linear function on an interval starting away from zero, a reversed interval and a zero-width interval. These exercise weights, node locations and orientation. The quadratic pump case then tests a nonzero, predictable approximation error.

A corrected routine follows. Its structure deliberately mirrors the formula. The function passed as f uses numerical values in agreed units; the integration routine itself has no knowledge of litres or minutes.

from math import isfinite, isclose

def trapezoid(f, u, v, n):
    if type(n) is not int or n < 1:
        raise ValueError("n must be a positive integer")
    if not (isfinite(u) and isfinite(v)):
        raise ValueError("bounds must be finite")
    h = (v-u)/n
    if not isfinite(h):
        raise ValueError("panel width must be finite")
    values = [f(u)]
    for i in range(1, n):
        values.append(f(u+i*h))
    values.append(f(v))
    if not all(isfinite(y) for y in values):
        raise ValueError("sampled values must be finite")
    total = (values[0] + values[-1])/2
    for y in values[1:-1]:
        total += y
    result = h*total
    if not isfinite(result):
        raise ValueError("result must be finite")
    return result

The explicit integer check also rejects True, which Python otherwise treats as an integer in arithmetic. The list contains the two endpoints and all interior samples. The slice values[1:-1] selects the interior values only. When n=1, it is empty, leaving the single trapezoid. Exceptions raised by f itself remain visible: a failure to evaluate the model should be investigated.

With u=v, the result is zero when the sampled model value is finite. Reversing the bounds makes h negative and reverses the node order; the result changes sign. These are mathematical properties of the signed integral, not special cases to correct by taking an absolute value.

assert isclose(trapezoid(lambda t: 2, 1, 3, 4),
               4.0, rel_tol=0.0, abs_tol=1e-12)
assert isclose(trapezoid(lambda t: t, 1, 3, 2),
               4.0, rel_tol=0.0, abs_tol=1e-12)
assert isclose(trapezoid(lambda t: t, 3, 1, 2),
               -4.0, rel_tol=0.0, abs_tol=1e-12)

Here the small tolerance allows floating-point arithmetic in exact benchmarks of this modest scale. It is not a physical uncertainty claim. An assert stops an ordinary run when its condition is false, helping you locate a failed check. The routine's explicit input guards are kept separate from these development tests.

Activity 12.11 · Repair and explain · 60 minutes Python

In the notebook, retain a copy of the flawed routine and record a failing test. Implement your repair before comparing it with the version above. Add tests for a zero-width interval, an invalid panel count and a non-finite sampled value. Use the pump model to check Q3=6.625 L. For each defect, explain which test exposes it and why. Restart the notebook and run all cells in order.

Discussion of Activity 12.11

A useful record includes the observed wrong constant-function result, the shifted-linear test after the first repair, and the final expected outputs. A zero-width interval returns zero for a finite model. Counts 0, −1, 2.5 and True should raise ValueError; a function returning infinity should also be rejected. The pump test should reproduce 6.625 L without rounding inside the routine. A successful repair includes this reasoning and clean execution, not just a copy of the final code.

12.12 Explore resolution and input changes

Once the implementation passes independent benchmarks, investigate resolution. For the pump model at three minutes, use panel counts 3, 6, 12 and 24. Compare each answer with the exact baseline 6.75 L. The expected absolute errors are 0.125, 0.03125, 0.0078125 and 0.001953125 L. The factor of four is justified here by the quadratic formula from Lesson 1.

Now hold the panel count at 24 and vary the input coefficients over Lesson 2's stated ranges. You should find changes of order hundredths of a litre, much larger than the remaining quadrature error of roughly two thousandths of a litre. This comparison tells us where effort is likely to matter: reducing numerical error by another factor of four would do little to narrow the range due to those inputs.

Example 12.8 · A numerical value with two separate qualifications

At the baseline inputs, 24 panels give 6.748046875 L. The known quadrature error is −0.001953125 L. Over the allowed coefficient rectangle, the exact model amounts range from 6.645 to 6.855 L.

A defensible report can give the baseline amount as 6.75 L, explain the numerical check, and state the separate input-dependent range. It should not combine these by adding percentages with unrelated reference scales. If we instead report the range of 24-panel approximations, the two endpoints are approximately 6.6430078125 and 6.8530859375 L. Each is below its corresponding exact value, and its error uses the relevant b, rather than the baseline b.

Remember the missed-feature example in Unit 11. A function can be finite at every sampled point while a narrow feature lies between them. Finite-value guards and a small change under refinement do not test everything. Inspect the definition, the domain and the actual sample positions. Split at known changes or place samples where the model says structure occurs.

Activity 12.12 · Two investigations, one report · 60 minutes Python

Produce a resolution table at the baseline coefficients and a separate input table at 24 panels. Predict each table's pattern before running it. Include an independently calculated row in each table. Explain the numerical tolerance you would use for the model integral and what further information would be needed to judge real delivered water to 0.01 L. Discussion of Activity 12.12

The baseline values are 6.625, 6.71875, 6.7421875 and 6.748046875 L. For the baseline, 12 panels already give quadrature error below 0.01 L; 24 provide a margin. The input range permits ±0.105 L in the exact amount, so a real-water claim at 0.01 L would require better evidence about coefficients, model fit and losses. Your report should retain separate explanations for numerical resolution and input sensitivity. State assistance factually; no particular tool or generated solution is required.

Repairing the program has produced more than a better number. We have a record of why the original test was weak, what changed, which benchmarks support the repair and which questions lie outside its reach. The final lesson will turn that record into a concise judgement and ask you to transfer the checks to another supplied model.
