P101 · Practical orientation

A place to calculate, explain and return

The purpose of this orientation is to make your working environment dependable before we ask it to do physics. You will open a notebook, run a small calculation, save an explanation and check that the result can be reproduced after a fresh start.

If you already use Python notebooks, keep your familiar environment. Open the supplied notebook, check its kernel, run it from a clean state and save/reopen it. There is no requirement to reinstall software or repeat a beginner’s setup. If notebooks are new to you, the route below gives a local starting point without a paid account.

What you need

Use a computer with a current browser, a keyboard and some writable storage, plus paper and a calculator. Python and JupyterLab are free, open-source tools. The local route needs internet access for installation and documentation; the small notebook itself runs locally after setup. Lesson 1 can be studied without this setup, and the first notebook needs no NumPy, plotting package or special equipment.

Create a folder you can find again, such as Physics/P101 inside Documents. Keep the original downloaded notebook and make a working copy with a descriptive name. A notebook is an ordinary file ending in .ipynb; saving it is different from leaving its browser tab open. Keep a second copy of important work in your normal backup location.

Preparing a local environment

Use an existing supported Python 3 installation if you have one. Otherwise obtain Python from the official Python download page and follow its installer instructions for your operating system. The commands below create a separate environment in your P101 folder, so the teaching tools do not need to share packages with unrelated projects. They are setup instructions, not programming syntax you need to memorise.

macOS or Linux setup

Open Terminal, move into your P101 folder and run these lines in order. cd changes the current folder; adjust the first line if you chose another location.

cd ~/Documents/Physics/P101
python3 -m venv .venv
.venv/bin/python -m pip install jupyterlab
.venv/bin/python -m jupyterlab

The first command assumes you have already created the folder. If python3 is not found, finish the Python installation and reopen Terminal. If Linux reports that venv is unavailable, use your distribution’s instructions for its Python venv package rather than installing packages into the system environment.

Windows setup

Create the P101 folder first. Open PowerShell in that folder (use “Open in Terminal” in File Explorer where available), then run:

py -m venv .venv
.\.venv\Scripts\python.exe -m pip install jupyterlab
.\.venv\Scripts\python.exe -m jupyterlab

If py is unavailable but your Python installer supplied python, use python -m venv .venv for the first line. The remaining lines use the environment’s own executable. No activation script or PowerShell policy change is required.

JupyterLab normally opens a local browser address. Keep its terminal running while you work. If the browser does not open, follow the local URL printed by JupyterLab; the address refers to your own machine. The file browser should show the folder from which you launched it. Place the downloaded notebook there, or use JupyterLab’s upload control.

If you prefer an existing editor with notebook support, select its Python 3 kernel and follow the same exercise below. A kernel is the running process that executes the code. A notebook document and its kernel are different things: a saved document can contain old output even when no kernel is running.

Open, predict, run

Download the P101 orientation notebook. Its first code cell contains 12 / 4, a deliberately simple calculation. Predict 3 before running it. Select the cell and use the Run control or Shift+Enter. A result such as 3.0 is normal: Python’s division produces a floating-point value here.

The document also contains text cells, called Markdown cells. Double-click a text cell to edit its explanation, then run the cell to display the formatted text. Code cells execute Python; text cells explain the question and interpretation. The two cell types have different jobs even when they appear next to one another.

Change the calculation to 20 / 4, predict the result and run it again. Then edit it back to 12 / 4 without running the cell. The old output can still say 5.0. You have now made a small example of a misleading notebook: the visible code and visible output disagree. Run the cell again to repair it.

Working habit · Output can be stale

Editing an input does not necessarily recalculate the output. Before trusting or sharing a notebook, restart its kernel and run all cells from top to bottom. Save after that clean run so the saved code and output describe the same calculation.

Save, restart and reopen

  1. Add a sentence to the notebook describing what you changed and what you expected.
  2. Save the notebook under your working filename.
  3. Use the Kernel menu’s restart-and-run-all command (wording may differ between notebook applications). Confirm the restart. Check that the arithmetic output is 3.0 after restoring 12 / 4.
  4. Save again, close the document and reopen it from the file browser. Confirm that your explanation and output are present.
  5. Read the final environment-information cell. It reports the Python version and executable used by the kernel. This is diagnostic information, not code to learn yet.

A clean run is a check of execution order. Later notebooks will store intermediate values, and running cells in a different order can conceal a missing step. Reopening a saved file checks something else: that you can actually recover the document. Neither check proves a physical model correct; that will require the reasoning and independent comparisons developed in the lessons.

When something goes wrong

If a code cell remains busy, use the interrupt command in the Kernel menu. If it will not recover, save the document and restart the kernel, then run from the top. If Python reports an error, read the final line and identify the cell it belongs to before changing anything. For this notebook, check that ordinary slashes and digits were entered in a code cell, not a text cell.

If your notebook opens with an unavailable kernel, select an installed Python 3 kernel. In the local JupyterLab environment above, the supplied Python kernel is sufficient. If the application behaves differently from these instructions, retain the notebook and the exact error text so that we can work through it together. There is no need to resolve setup by trial-and-error changes to unrelated software.

For a screen-reader or keyboard workflow, JupyterLab provides menu commands as alternatives to toolbar icons, and the orientation notebook uses only text and simple code output. If the notebook interface is unsuitable, the plain Python companion contains the same arithmetic and environment check; keep your explanation in a text file and run it with your chosen Python editor. The companion does not reproduce notebook cell behaviour, so use the written explanation above to understand that limitation.

Ready to use the tools

You are ready for the first coding lesson when you can locate your working file, run its calculation in the intended Python environment, explain the result, save it, and recover it with matching output after a clean run. These are practical working checks, not an examination or a gate that delays your physics reading.

The module’s separate six-hour orientation allocation includes reading the module introduction, setup, file organisation, practice and troubleshooting. Experienced users may need much less setup time; use the tools you already trust. The allocation is a planning allowance, not a requirement to spend six hours installing software.
