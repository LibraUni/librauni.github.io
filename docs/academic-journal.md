# Academic journal contract

Academic only: tutoring/content discussions, exercises, knowledge and skills, misconceptions/difficulties, feedback, assessments, reflections and learning milestones. Exclude website design, programme planning and administrative chat. No invented retrospective timestamps or claims of mastery.

Private append-only users/{uid}/journal entries contain schemaVersion, category, title, body, area, evidence, nextSteps, reported source, optional occurredAt, optional corrects and server recordedAt. Corrections append a new linked entry. Client source labels are reported, not proof of assessor identity. The journal does not grant assessed attainment or awards.

/journal/ reads all pages of the academic journal plus existing attempts/assessments/progress. It derives completion-mark changes from planner revisions, excluding administrative schedule changes. Profile/planner/note snapshots remain in full raw-record exports, outside the academic timeline. Historic overwritten progress with no revision cannot be reconstructed. UTC date filters use event time when supplied, else recorded time; unknown times stay in unfiltered exports. Render text safely, never as submitted HTML. JSON exports preserve structure; Markdown provides readable full content. Filtered downloads include all matching entries, not only the visible page.

External chat cannot be captured by the website. Connected tutors must archive available full academic transcript text and a separate evidence-based session observation after academic sessions, using scripts/archive-academic-session.mjs or the owner's journal import. Obtain exact transcript from the active supported conversation export when available; preserve speaker attribution and original timestamps. Do not label a summary a full transcript. If full text or times are unavailable, explicitly record the coverage gap and request/import an export rather than fabricate it. No current administrative conversation is archived as tutorial evidence.

The CLI takes a private JSON file outside the public repository and validates by default; --write uses the authorised Firebase CLI account. It resolves the one existing private profile as recipient, fails if ambiguous, uses content-derived batch IDs and create-only writes. Long transcripts use transcriptParts from src/journal-data.js without text truncation. No privileged tokens, session text or learner IDs are printed by the uploader. Review input category/scope before upload. Keep original session input privately until verified online.

Existing recursive database backups include the new collection automatically. Online exports need authenticated access; local unsaved drafts and unimported chats are not backed up. Browser import retries use stable batch IDs while pending; re-importing the same file as a new operation may create another archive. The tutor CLI deduplicates identical batches. No scheduled polling or transcript scraping is installed.
