An analysis another person can rerun

A graph is the visible end of an analysis. Behind it are a particular file, choices about its contents, a calculation and a sequence of instructions. To make the result useful to someone else, we need to preserve that route as carefully as the figure itself.

Lesson 3 compared a constant-velocity model with four invented observations. It separated the observations from predictions and interpreted the signed residuals. Now imagine handing that notebook to a colleague. A saved graph may open perfectly while the calculation fails: the data file is elsewhere, a value exists only in your running session, or a missing entry has been quietly replaced. Our task is to make these dependencies visible and remove accidental ones.

Allow four hours: 45 minutes for explanation and examples, 45 for written activities, 120 for the notebook repair and 30 for feedback and correction. Read the code slowly before running it; the two-hour practical begins in Activity 3.23. You will use the same free local Python, NumPy, Matplotlib and notebook tools as before. There is no new physics or fitting method, and no paid service is required.

Download and extract the Lesson 4 working folder. It contains a deliberately broken repair notebook, an equivalent repair script, a data folder and README.txt. Choose the notebook or script route, not both. The teaching below develops the methods needed to repair them. The errors are part of the activity; the files are not a finished analysis.

3.19 Preserve the route from file to claim

Suppose you receive a picture labelled “model comparison”. You can inspect its axes and points, but you cannot tell which file supplied the observations, how blank entries were treated, or whether the line uses the parameters described in the caption. A notebook adds executable instructions, but even that is insufficient if its inputs and working conditions are absent.

Here, a rerunnable analysis means an account that lets another person start with the identified input files, follow the stated instructions in a fresh Python session, and obtain the stated numerical results. This is a practical meaning for this lesson, not a claim that terminology is used identically throughout science. Nor does successful rerunning establish physical truth. Two people can reproduce the same sign error. The calculation still needs the independent checks and physical interpretation developed earlier.

Keep three roles distinct. The source record preserves what was supplied. The analysis says what was selected and calculated. The outputs show what that calculation produced. If we edit the source to make the calculation easier, a later reader loses the evidence needed to understand the edit. Instead, leave the source unchanged and express justified selections in code, with an explanation.

The provenance of a result is its traceable history: where its inputs came from and what was done to them. For our small investigation, a short readable note and a clearly organised folder are enough to begin. A result named final.png does not supply that history. A note identifying the record, its units, a selection rule and the model does.

Example 3.13 · What belongs with the picture?

Question. A colleague receives a position–time graph and the statement “I removed one bad point.” What is missing, and how could the statement be repaired?

Reasoning. “Bad” does not identify a row or a reason. It might mean an absent reading, an impossible entry or merely a point that disagrees with the model. These require different decisions. The reader also needs the original record, the code that generated the plot, and its conventions.

A usable account. “This uses invented record P101-U03-L04-B, version 1. The position field at 16 s is blank in the supplied file. I retained that row in the source and omitted it only from comparisons requiring a position. No value was substituted. Times are seconds; positions are metres from the fixed rail origin, right positive. M1 is retained from Lesson 3.” This can be checked against the file and the program. It does not pretend to know why a real instrument might have missed a reading.

3.20 Make the file location explicit

A filename is meaningful only relative to a place to look. Python has a current working directory: the folder from which relative paths are interpreted. This need not be the folder visible in a separate file-browser window. In particular, opening a script in an editor does not by itself guarantee that its execution starts in the script’s folder.

Path.cwd() obtains the working directory; the slashes in the next line join folder and filename components. Before loading, inspect data/record.csv as text. It has this exact content:

This is P101-U03-L04-B, a deliberately incomplete teaching copy of the earlier invented record. The 16 s position has been withheld to create a missing-data case. It is not a new experiment and does not revise the earlier record. Treat the blank as unavailable in this exercise; do not fill it from memory. The comma on that row preserves the empty second field. Removing the comma would change the row structure.

loadtxt, used for the complete table in Lesson 2, expects numeric entries and will reject this blank. genfromtxt can represent a missing numeric field. We choose floating-point values and explicitly use np.nan, “not a number”, for missing entries. The header option here is skip_header, not loadtxt’s skiprows. As before, ndmin=2 keeps the loaded result two-dimensional. The argument loose=False makes an unexpected nonnumeric token an error instead of quietly accepting it as a failed conversion.

raw = np.genfromtxt(
    data_path, delimiter=",", skip_header=1, dtype=float,
    filling_values=np.nan, ndmin=2, loose=False
)
print("Rows, columns:", raw.shape)
print(raw)
if raw.shape != (4, 2):
    raise ValueError("Expected four data rows and two columns; inspect the file.")

time_all_s = raw[:, 0]
position_all_m = raw[:, 1]
if not np.all(np.isfinite(time_all_s)):
    raise ValueError("A clock reading is missing or non-finite; inspect the source.")

raw.shape gives the numbers of rows and columns. For this specified file, it should be (4, 2). The first check stops with an explanatory ValueError if that structure differs. The instruction raise deliberately stops execution with an error; it prevents later steps from pretending that an unexamined input is acceptable. This is a check for this exercise’s file, not a universal CSV validator.

The two slices select the time and position columns, just as in Lesson 2. np.isfinite tests each entry for an ordinary finite number; np.all asks whether every test is true. We require all four clock readings to be available so that even an omitted position can be located in time. A missing time stops this analysis for inspection. The code does not check units, origin or the correctness of the recorded times: those still require the source description and a comparison with the table.

3.21 Keep a missing reading missing

In the loaded position column, the blank becomes nan. It is not a measurement at the origin, a small number, or an instruction to delete a row from the source. Here it marks the absence of a usable numeric position. In other calculations, nan can also result from an invalid numerical operation, so its meaning must be traced to its source. The None marker used in Unit 2 served a related bookkeeping role in ordinary records; we now use a marker that fits a floating-point array. Subtracting a prediction from it still produces nan: there is no observed value from which to form the residual.

For the present comparison, we can use the three complete pairs, provided we say what has been left out. This restricted choice is different from declaring the incomplete record equivalent to a complete one. If missing observations tend to occur at difficult moments, analysing only the available ones could hide important behaviour. Here the omission is deliberately constructed; in an experiment its cause would need investigation.

Selection rule · Keep complete pairs together

For each row, require a finite clock reading and a finite position. Use the same row selection for both columns. Preserve the source file, identify the omitted time, and do not replace an absent observation with zero or with a model prediction.

The rule becomes an array of True and False values, called a Boolean mask. Each entry answers “May this row participate in this comparison?” The & combines the two arrays of tests entry by entry: both must be true. This is different from applying Python’s scalar and to whole arrays.

usable = np.isfinite(time_all_s) & np.isfinite(position_all_m)
time_s = time_all_s[usable]
position_m = position_all_m[usable]
print("Usable pairs:", len(time_s), "of", len(time_all_s))
print("Times without a usable position / s:", time_all_s[~usable])
if len(time_s) == 0:
    raise ValueError("No complete pairs are available for comparison.")

Square brackets containing a Boolean mask select the entries whose corresponding mask values are true. The same usable mask therefore keeps the time and position from each selected row together. The ~ reverses the mask, allowing us to print the time associated with the unavailable position. The guard against zero complete pairs avoids presenting an empty comparison as a result.

The selected times are 10, 14 and 19 s, and the selected positions are −2, 4 and 1 m. Their unequal time gaps must survive into the graph. Removing only the missing position and taking the first three times would falsely pair the final position with 16 s. Both arrays would then have length three, so a length check alone would miss the error.

Example 3.14 · Zero would invent a disagreement

Question. M1 predicts 7 m at 16 s. What residual follows from the incomplete source, and what would replacing its blank with zero do?

Reasoning. A residual needs an observed position at that time. The source supplies none, so its residual is unavailable. If zero were inserted, the calculation would instead be

r=0m−7m=−7m

Interpretation. The −7 m value would be a consequence of an invented observation. It could appear as an apparently informative point far below the model. Substituting M1’s prediction would be equally misleading: it would manufacture a zero residual and artificial agreement. We may calculate the 7 m prediction, but we cannot relabel it as a supplied observation.

3.22 Rebuild the calculation in order

A notebook has two kinds of state that are easy to confuse. Its saved document contains cells and possibly old outputs. Its kernel, the running Python process, holds values created by executed cells. Editing a cell changes the document; it does not execute that cell or update every result that once depended on it.

Suppose a calculation cell evaluates a prediction using a velocity of 1.5 m/s. Later you change the velocity to 0, but rerun only a cell that prints the existing prediction. The old array remains. Python assignment evaluated the earlier expression at that time; it did not establish a permanently updating algebraic relationship. A displayed figure can likewise remain on screen after its source values have changed.

Example 3.15 · A result left behind

Question. Three cells are executed in the order shown. What does the last cell print?

velocity = 1.5
prediction_at_19 = -2 + velocity * (19 - 10)

velocity = 0.0

print(prediction_at_19)

Working. The first calculation uses 1.5 and assigns 11.5 to prediction_at_19. The second cell changes only velocity. The final cell therefore prints 11.5, not −2. To obtain the zero-velocity prediction, the calculation itself must be executed again after changing the input.

Interpretation. The value is not random and Python has not ignored an instruction. It is the result of a particular execution history. A reader seeing only the final value of velocity could nevertheless attach the wrong meaning to it.

A clean run starts a fresh kernel and executes the intended analysis from top to bottom. In JupyterLab, use the command Restart Kernel and Run All Cells, available through the menus or command palette. Other notebook interfaces may use slightly different wording. Save your edits first. Clearing visible outputs alone does not reset the kernel’s variables; closing a browser tab does not reliably terminate the kernel either. For the script route, run the saved script in a new Python process from the documented working directory.

Arrange the notebook so that each cell can use values defined above it: imports and location, loading, inspection and selection, model, figure, then run notes. A clean run that fails because a name is undefined reveals a missing or misplaced step. Read the first error and repair its cause; running later cells from an old session may merely conceal it. Execution counters can warn about an unusual order, but are not a certificate that outputs match the current edited text.

For the incomplete record we retain the same M1 from Lesson 3. Its reference values and velocity are made explicit below. We do not choose new endpoints after selection or quietly change the model to improve the remaining agreement.

def predict_position(times_s, t_ref_s, x_ref_m, velocity_m_per_s):
    return x_ref_m + velocity_m_per_s * (times_s - t_ref_s)

# M1 is retained from Lesson 3, not re-estimated after selection.
reference_time_s = 10.0
reference_position_m = -2.0
velocity_m_per_s = 1.5
predicted_m = predict_position(
    time_s, reference_time_s, reference_position_m, velocity_m_per_s
)
residual_m = position_m - predicted_m
print("Clock readings / s:", time_s)
print("M1 predictions / m:", predicted_m)
print("Residuals (observed - predicted) / m:", residual_m)

The predictions for the retained times are −2, 4 and 11.5 m; the residuals are 0, 0 and −10.5 m. Check the final entry by hand: nine seconds after the reference event, displacement is +13.5 m and position is 11.5 m, leaving the observed 1 m lower by 10.5 m. The missing row changes which comparisons are available, not the definition of M1.

Use a different kind of check as well: at the reference time the function should return the reference position, and with zero velocity it should return that position for every input time. These checks probe the formula’s structure. They complement a hand-checked ordinary case; neither one proves that every possible program input is handled or that the physical assumptions are true.

3.23 Leave a figure and an account of the run

Once the arrays are correct, the graph must communicate their meaning. A particularly plausible mistake is to plot positions against their array indices while labelling the horizontal axis as time. Indices 0, 1 and 2 identify entries; they do not stand for clock readings 10, 14 and 19 s. Equally spaced markers would conceal the unequal four- and five-second intervals between available observations.

Example 3.16 · Repair what the figure claims

Question. The left panel of Figure 3.17 joins the available positions at indices 0, 1 and 2, but calls that axis “Clock reading / s”. Suppose its caption also says “The model follows the observations.” What needs changing?

Reasoning. Supply the actual time array, retain position units, and identify which data are absent. Joining observations asserts an intervening history that the file does not provide, so use separate markers. A model must be drawn from its prediction array and labelled with its own rule; a line joining observations is not evidence of model agreement.

Interpretation. The repaired panel makes a narrower, checkable claim: three available invented positions at their stated times, without a supplied position at 16 s. A separate M1 line and residual panel can then show the actual comparison. A prettier title alone would leave the numerical misrepresentation intact.

The following figure code reuses Lesson 3’s two-panel construction. The line is evaluated at drawing times between 10 and 19 s; residuals use only predictions at the retained observation times. The 100 drawing points are not observations. The title identifies the incomplete record and counts the available positions. There is no residual marker at 16 s, and the caption below explicitly explains why.

line_time_s = np.linspace(10, 19, 100)
line_position_m = predict_position(
    line_time_s, reference_time_s, reference_position_m, velocity_m_per_s
)
fig, axes = plt.subplots(2, 1, sharex=True, figsize=(7, 7), layout="constrained")
position_ax = axes[0]
residual_ax = axes[1]
position_ax.plot(time_s, position_m, "o", label="Available invented positions")
position_ax.plot(line_time_s, line_position_m, "--", label="M1: retained A-B rate")
position_ax.set_ylabel("Position / m")
position_ax.set_title("P101-U03-L04-B: 3 of 4 positions available")
position_ax.legend()
position_ax.grid(alpha=0.3)
residual_ax.plot(time_s, residual_m, "o")
residual_ax.axhline(0, color="grey", linewidth=1)
residual_ax.set_ylabel("Residual: observed - predicted / m")
residual_ax.set_xlabel("Clock reading / s")
residual_ax.grid(alpha=0.3)
fig.savefig(project_dir / "p101-u03-l04-result.png", dpi=160)
plt.show()

Rebuilding an output is expected; overwriting the original CSV is not part of this workflow. Changes in fonts or software versions may alter the picture’s appearance without changing the numerical comparison. Inspect both the numbers and the meaning of the labels rather than demanding identical pixels.

A wider view · From an instrument record to an analysis

A flight-research result began before a graph was drawn. Instruments had to be prepared, their records read, and quantities carried through to an analysis. NASA’s account of the early D-558 work describes human “computers” converting markings on films into data sheets and graphs for engineers.

Our files are much smaller and our observations invented, but the distinction remains useful: acquiring a record, converting its representation and interpreting its implications are different operations. Keeping their history visible makes an analysis open to examination. A convenient program does not remove responsibility for the choices between those stages.

Discussion of Activity 3.23

A defensible conclusion is: “For invented incomplete record P101-U03-L04-B version 1, M1 retains the A–B rate +1.5 m/s and reference event (10 s, −2 m).
