Lesson 6
Putting an executable model together

A number on a screen is the end of a chain of decisions. Which object did we describe? Where did we place the origin? Which units did we use? What did we assume stayed constant? A useful scientific notebook makes that chain visible, so that another reader can follow the result and challenge it.

Unit 1 began with the meaning of a physical value. We then built a simple motion model and learned enough Python to express it, repeat it and test parts of its behaviour. The closing task is to bring those ideas together without adding new syntax. The aim is an account you can explain, not merely a program that finishes.

Allow about three hours: 15 minutes for synthesis, reference and conclusion; 60 minutes for the integrated notebook; 75 minutes for the cumulative written exercises; and 30 minutes for feedback and correction. These are estimates, not a time limit. The notebook and exercise set are distinct parts of this allocation. Download the Lesson 6 notebook, the Python working template and the Unit 1 reference PDF. Nothing is submitted automatically.

1.31 Make the chain of reasoning visible

A notebook should tell us what its numbers stand for before it asks us to trust them. Begin with the physical question and the conventions. Give the chosen model and its conditions. Then supply the implementation, show checks whose answers are known independently, and interpret the results. Putting these parts in separate cells helps inspection, but their connection is the important feature.

Keep three kinds of statement distinct. A stipulated input is supplied for a teaching case. A prediction follows from a model and inputs. A measured value comes from an observation procedure. Labelling a list “data” does not establish which kind it contains. In this lesson the inputs and comparison observations are invented explicitly; they are not evidence from a real experiment.

Example 1.29 · An inspectable claim

Compare “the answer is 7” with this statement: “For a point initially at −1 m at clock reading 6 s, assuming a constant signed rate of +2 m/s relative to a fixed laboratory origin with positive direction right, the predicted position at 10 s is +7 m.” The second statement can be checked. Four seconds elapse; the displacement is +8 m; adding it to −1 m gives +7 m.

It still does not establish that a real object moved that way. An observation would need an identified object or mark, a spatial reference, start/end events and a measurement procedure. Explicit wording makes missing evidence visible rather than supplying it by implication.

A wider view · What a test setting tells us

In Lesson 5 this image helped distinguish a controlled test from operation on Mars. Now ask a more specific question: what would have to accompany the image for somebody else to interpret a test result? We would need the command, the recorded response and the conditions under which the test was carried out. The picture alone cannot supply those details.

The same distinction applies to our notebook. A clean output is useful, but the inputs, units, assumptions and checks give it scientific meaning. Unit 2 will examine how readings are obtained and how their limitations enter that account.

1.32 Build an explained notebook

The model remains x=x0+v(t−t0). Use finite numerical inputs in metres, seconds and metres per second, with paired initial position and time. Our stipulated constant rate applies from the initial event onwards; the caller must reject earlier requests. The function performs arithmetic and returns a number. Its docstring states responsibilities, but does not enforce them.

Work from the task below before looking at the solution. You may consult earlier lessons for syntax. Keep a written prediction beside the implementation: independently known answers make a run informative. No plotting, new packages or error-handling machinery are needed.

Activity 1.34 · A notebook another reader can follow

A tracked point starts at +2.5 m at clock reading 8 s. Its stipulated signed rate is −0.25 m/s thereafter. The laboratory origin is fixed and positive direction is right. Requests are [16.0, 6.0, 8.0, 20.0, 16.0, 18.0] seconds.

  1. Spend about ten minutes writing the physical account and predicting every accepted time/position pair and refusal. Distinguish position from displacement.
  2. Use about thirty minutes to write a returning function, a guarded loop and paired result lists. Label outputs with units; explain every list and condition. Keep zero and repeated results.
  3. Use ten minutes to check the initial event, zero rate, ordinary and negative-position cases. Test empty input and an all-earlier list separately. Predict what changes if requests arrive in a different order.
  4. Use ten minutes to save, restart, run every cell in order and inspect the results. Record what this proves about execution and what it does not prove about motion. Explain how you would investigate a later observation that disagreed.

The final deliverable is your own working notebook and a short interpretation, not a formal assessment submission.

Hint for Activity 1.34

All positions use the same initial event. The negative rate changes the coordinate by −1 m every four seconds. Initialise both result lists before the loop, and append to both only after the time condition accepts a request.

Discussion of Activity 1.34

The 6 s request is earlier than the initial event and is refused. The other requests give:

A suitable implementation is:

def position_m(x0_m, v_m_per_s, t0_s, t_s):
    """Return position / m at a constant signed rate.

    Caller uses finite m, m/s and s inputs, common origins,
    and checks t_s >= t0_s before calling.
    """
    elapsed_s = t_s - t0_s
    return x0_m + v_m_per_s * elapsed_s

x0_m = 2.5
v_m_per_s = -0.25
t0_s = 8.0
requests_s = [16.0, 6.0, 8.0, 20.0, 16.0, 18.0]
accepted_s = []
positions_m = []
for t_s in requests_s:
    if t_s >= t0_s:
        predicted_m = position_m(x0_m, v_m_per_s, t0_s, t_s)
        accepted_s.append(t_s)
        positions_m.append(predicted_m)
    else:
        print("No prediction at", t_s, "s: before initial event.")
print("Accepted times / s:", accepted_s)
print("Positions / m:", positions_m)

The initial-event result is +2.5 m. Setting the rate to zero leaves it at +2.5 m even at 20 s. The ordinary 16 s case gives +0.5 m; the 20 s case gives −0.5 m. Empty input makes no calls and prints empty lists; [6.0, 7.0] prints two refusals and empty lists. Reordering requests reorders accepted pairs, without changing the result for a given time.

A clean run shows that the saved code can reconstruct the outputs without an earlier interactive state. It does not establish the supplied rate, constant motion or correct physical input units. For a disagreement, check pairing, units and origins first, then implementation, then investigate whether the model or observations need revision. Do not silently change a reading to agree with the model.

1.33 Unit 1 exercises: choose and justify the method

These exercises cover the whole unit, not only functions. Allow 75 minutes for first attempts, using paper and a calculator where useful. Trace the short code by hand before checking it in Python if needed; the sixty-minute notebook allocation belongs to Activity 1.34. All twelve exercises are core practice. Suggested times total 75 minutes. Keep your initial answers, then use Section 1.34's correction period to compare reasoning as well as results.

State units, signs and conditions where relevant. For an explanation question, a clear reason is part of the answer. Hints and solutions are separate so that you can ask for a small prompt without immediately seeing the full argument.

Exercise 1.1 · Recover the meaning

A record says “position = 24; time = 5; rate = 2”. Give two physically different interpretations with consistent units. State two reference or procedure details needed before using it as an observation.

Suggested attempt: 4 minutes.

Hint for Exercise 1.1

Changing a unit changes what the same numeral represents. Is the time a clock reading or a duration?

Solution to Exercise 1.1

One interpretation is position 24 m at clock reading 5 s, with rate 2 m/s. Another uses position 24 cm and rate 2 cm/s at 5 s. The rates differ by a factor 100. Specify the origin and positive direction, the tracked mark, and what event/time origin the clock reading refers to. A bare set of numbers cannot establish a repeatable observation.

Exercise 1.2 · Convert a compound unit

A stipulated feed rate is 1.8 cm/min. Express it in m/s, then find the displacement in 40 s at that constant positive rate. Check by reversing the conversion.

Suggested attempt: 6 minutes.

Hint for Exercise 1.2

Convert centimetres to metres and minutes in the denominator to seconds.

Solution to Exercise 1.2

1.8 cm/min =0.018 m/60 s =0.0003 m/s. In40 s the displacement is 0.012 m, or 1.2 cm. Multiplying 0.0003 m/s by 60 s/min and 100 cm/m returns 1.8 cm/min. The result in 40 s is smaller than the 1.8 cm displacement in a full minute, as it should be.

Exercise 1.3 · Area is not length

A sensor face is 12 mm by 30 mm. Find its area in mm², cm² and m². A note claims that dividing the mm² value by 1000 gives m². Identify and repair the error.

Suggested attempt: 6 minutes.

Hint for Exercise 1.3

Either convert both lengths or square the length conversion factor.

Solution to Exercise 1.3

The area is 360 mm². The sides are 1.2 cm and 3 cm, giving 3.6 cm², or 0.012 m and 0.030 m, giving 0.00036 m². A square millimetre is one millionth of a square metre. Dividing by 1000 gives 0.36, a factor 1000 too large; both dimensions require conversion.

Exercise 1.4 · Compare scales

A 1.5 km route is marked at ideal intervals of 0.50 mm. How many intervals fit? Express the result in scientific notation. Check its order of magnitude by rounding the route to 1 km and interval to 1 mm. Explain why dividing 1.5 by 0.50 before converting does not answer the question.

Suggested attempt: 6 minutes.

Hint for Exercise 1.4

A count is dimensionless only after the length units cancel.

Solution to Exercise 1.4

1500 m divided by 0.00050 m gives 3,000,000 =3×10⁶ intervals. The bare-number quotient 3 still carries the ratio km/mm, which contributes another factor 10⁶. The rough 1 km/1 mm estimate is one million intervals, the same order of magnitude as the calculated three million. These idealised counts ignore gaps, bends and endpoint-marker counting; intervals and markers are not the same count.

Exercise 1.5 · Signed position and the initial event

A point is at −3 m when a clock reads−2 s and has constant rate+0.5 m/s. Predict its position at 4 s. Then move the spatial origin 2 m to the right without changing direction: give both initial and final coordinates and the displacement in that convention.

Suggested attempt: 6 minutes.

Hint for Exercise 1.5

Find the duration first. A shifted origin subtracts the same amount from both positions.

Solution to Exercise 1.5

The duration is 6 s, displacement+3 m and final position 0 m. With the new origin, the initial coordinate is−5 m and the final coordinate−2 m. Their difference remains+3 m. The negative initial clock reading does not make the duration negative; changing the spatial origin does not change the motion.

Exercise 1.6 · Challenge a formula

Two candidate position expressions are x₀ + vt and x₀ + v(t−t₀). Both pass a zero-rate check. Choose one nonzero-time-origin case that distinguishes them; calculate both answers. Also explain why x₀ + v + (t−t₀) fails a units check.

Suggested attempt: 7 minutes.

Hint for Exercise 1.6

Use an initial-event check with nonzero rate and nonzero t₀.

Solution to Exercise 1.6

For x₀=2 m, v=0.5 m/s and t=t₀=4 s, the first gives 4 m and the second 2 m. At the initial event the position must remain 2 m, so the first expression fails this case. The sum x₀+v+(t−t₀) tries to add metres, metres per second and seconds. Different dimensions cannot be added as positions. Passing a units check would still not prove a formula physically correct.

Exercise 1.7 · Separate a prediction from evidence

A model predicts positions 0,1,2 m at times 0,2,4 s. Invented comparison readings are 0,1,2.6 m at those times. The code runs cleanly and passes initial-event and zero-rate checks. What agrees, what disagrees and what should be investigated? Can these readings establish the cause?

Suggested attempt: 6 minutes.

Hint for Exercise 1.7

An implementation check and a comparison with observations ask different questions.

Solution to Exercise 1.7

The first two pairs agree; at 4 s the reading is 0.6 m above the prediction. Check event matching, units, origin and transcription, examine the implementation, and investigate changing motion and the measurement procedure. The given values alone do not identify a unique cause or decide whether the discrepancy exceeds measurement limitations; no uncertainties or real procedure were supplied. Do not claim that a successful run validates the model.

Exercise 1.8 · Trace a saved result

Trace a = 3.0, b = 2.0 * a, a = 5.0, then print(a, b). What prints? What changes if the b assignment is executed again? Explain why decimal spelling does not establish measurement precision.

Suggested attempt: 6 minutes.

Hint for Exercise 1.8

An assigned numeric result is not a live formula.

Solution to Exercise 1.8

The first output is 5.0 and 6.0. Re-executing b=2.0*a makes b10.0. Changing a alone does not recalculate b. A float describes representation; the decimal point does not state an instrument resolution or uncertainty. A clean restart/run helps expose stale dependencies but cannot supply missing physical meaning.

Exercise 1.9 · Retain the pairings

Using x₀=1 m, v=−0.5 m/s, t₀=2 s, requests are[6,1,2,6]s. Give accepted times and positions. Explain the outcome if the position list is reset inside every accepted iteration. Would equal list lengths alone prove correct pairing?

Suggested attempt: 7 minutes.

Hint for Exercise 1.9

Calculate each request from the fixed initial event.

Solution to Exercise 1.9

Accepted times are[6,2,6]s and positions[−1,1,−1]m. The 1 s request is refused. Resetting only the position list inside each accepted iteration leaves just[−1]m, while a separately accumulated time list still has three entries. Equal lengths are necessary for these paired lists but not sufficient: one list could have been sorted or reordered separately.

Exercise 1.10 · A return is not a display

A function calculates a local variable result, prints it and reaches its end without return. The caller assigns its call to saved. What does saved contain? Does a same-named outside result automatically change? Explain how to make the calculation reusable.

Suggested attempt: 7 minutes.

Hint for Exercise 1.10

Trace what crosses from the function back to the assignment.

Solution to Exercise 1.10

saved contains None, even if a number appeared on screen. A local numeric assignment does not replace an outside binding with the same name. Return the computed number and let the caller store, combine or print it. None is not zero. If a function instead mutates an input list, that is a different situation; local names do not imply a deep copy of objects.

Exercise 1.11 · An interface error

A function expects m and s. A point starts at−2 m at time 0 and moves at+0.25 m/s. A caller supplies the number 3 intending minutes. Find the incorrectly interpreted position, the correct position and their difference. Does a nonnegative-time check reveal the mistake?

Suggested attempt: 7 minutes.

Hint for Exercise 1.11

Convert the intended time before calling; preserve the initial offset.

Solution to Exercise 1.11

The mistaken 3 s call gives−2+0.25×3 =−1.25 m. Three minutes is 180 s, giving−2+45 =43 m. The correct result exceeds the mistaken one by 44.25 m. Both numerical times are nonnegative, so the boundary check accepts both. Unit suffixes and docstrings guide the caller but do not attach physical units to a float.

Exercise 1.12 · Design checks you can defend

A friend accepts a model function after checking only x₀=0, t₀=0, v=1, t=1. Propose three further numerical checks with independently known results and different purposes. State one thing no such finite set of arithmetic checks establishes.

Suggested attempt: 7 minutes.

Hint for Exercise 1.12

Choose cases where common wrong expressions stop agreeing: nonzero origins, zero rate and negative rate.

Solution to Exercise 1.12

One set is: initial event x₀=2, v=0.5, t₀=t=4, expected 2 m; zero rate x₀=−3, v=0, t₀=2, t=9, expected−3 m; negative rate x₀=1, v=−0.5, t₀=2, t=6, expected−1 m. These challenge time-origin handling, initial-offset retention and sign handling. Other reasoned sets are valid. A finite set does not prove correctness for every input or establish constant motion in nature. Include caller-domain checks separately.

1.34 Use feedback to improve the account

Set aside thirty minutes for checking and correction. For each mismatch, identify the first point where your reasoning diverged: interpretation, conversion, model choice, arithmetic, program state or output pairing. Write one corrective sentence and redo the affected step. Copying the final answer leaves the original decision unexamined.

If conversion was the difficulty, revisit Lessons 1.2–1.3 and redo Exercises 1.2–1.3 with the unit factors visible. If signs or clock readings caused trouble, draw the chosen origin and trace the paired initial event in Lesson 2 before revisiting 1.5–1.6. For code state, returns or list retention, use Lessons 3–5 and explain each assignment before running it. These are targeted corrections within the feedback allocation, not a second compulsory exercise set.

For Activity 1.34, look for a coherent physical description, independently predicted results, a returning function, a correctly placed guard, intact pairs and a clean rerun. Then read the interpretation: does it distinguish a code check from a claim about motion? If time runs out, keep the unresolved point visible and return to it; the estimates are not a reason to conceal a difficulty.

1.36 From an executable model to a measurement

At the beginning of Unit 1, a number without a unit could not yet answer a physical question. We can now carry a statement through a longer chain: establish conventions, express a relationship, calculate predictions, repeat them with a program and challenge the results. The code has not removed the need for judgement; it has made some of our decisions explicit enough to inspect.

Our constant-rate model was intentionally modest. It let us separate position from displacement, a clock reading from a duration, and an implementation check from evidence about motion. Those distinctions will remain useful when the equations and datasets become more substantial. Reusable functions and readable notebooks will travel with us into later P101 and M101 work without requiring the modules to advance in lockstep.

Unit 2 asks the question we have mostly set aside: how were the input values obtained? Measuring a position or timing an event involves instruments, procedures and limitations. The next step is to investigate those, rather than treating every number handed to a program as exact knowledge about the world. Keep your Unit 1 notebook and corrections: they provide a concrete starting point for that investigation.
