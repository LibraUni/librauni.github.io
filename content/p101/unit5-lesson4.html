Comparing orbital models

A calculation becomes more useful when someone else can see what was held fixed, what was changed and how the result was checked. We will turn the circular-orbit equations into a small computational investigation whose conclusions are as explicit as its inputs.

Allow four hours: 45 minutes for the physical explanation, 45 minutes for written predictions, 120 minutes for the Python investigation including code reading, and 30 minutes for feedback and correction. The notebook and script are alternative ways to perform the same investigation. Neither requires a numerical orbit solver.

5.16 Build a transparent orbit function

In Lesson 3, arrays held several radii for one central source. A function lets us name that calculation and use it consistently. Before writing the function, specify its contract. Input mu is one positive gravitational parameter in m³/s². Input radius is a positive centre distance, or an array of such distances, in metres. Input body_radius is the positive radius of the ideal spherical source in metres. Only radii strictly outside its surface are accepted. Outputs are speed in m/s, period in seconds and field magnitude in m/s², in that order.

These checks catch several meaningless inputs before they enter a square root or division. They cannot decide whether a real planet is spherical enough, whether an orbit is circular, or whether an atmosphere can be neglected. A program can enforce a stated numerical domain; the author must still justify the physical model. A positive number entered in the wrong units will also pass a positivity check.

import numpy as np
import matplotlib.pyplot as plt


def circular_orbit(mu, radius, body_radius):
    """SI inputs; returns speed, period, field for exterior circles."""
    mu = float(mu)
    body_radius = float(body_radius)
    radius = np.asarray(radius, dtype=float)
    if not np.isfinite(mu) or mu <= 0:
        raise ValueError("mu must be finite and positive")
    if not np.isfinite(body_radius) or body_radius <= 0:
        raise ValueError("body_radius must be finite and positive")
    if radius.size == 0 or not np.all(np.isfinite(radius)):
        raise ValueError("radius must contain finite values")
    if np.any(radius <= body_radius):
        raise ValueError("each radius must be outside the source")
    speed = np.sqrt(mu / radius)
    period = 2 * np.pi * radius / speed
    field = mu / radius**2
    return speed, period, field

The formula lines are the same as the hand calculation. The lines above them explain how inputs are interpreted. float converts a scalar input to a floating-point number; np.asarray(..., dtype=float) gives an array representation for one value or a sequence. np.isfinite rejects infinity and undefined numerical values. np.all requires every entry to satisfy a condition; np.any detects whether even one entry fails the exterior-radius requirement. raise ValueError stops the calculation with a message rather than returning misleading values. Retrieve P101 Unit 1's function lesson if function inputs or returned values need refreshing.

A first test should have an answer that did not come from this function. The hand benchmark has μ=8×1012 m³/s², radius 2×106 m and expected speed 2000 m/s. Give the hypothetical source a radius of 106 m so the orbit lies outside it.

mu0 = 8.0e12
r0 = 2.0e6
R = 1.0e6
v0, T0, g0 = circular_orbit(mu0, r0, R)
assert np.allclose(v0, 2000.0, rtol=1e-12, atol=0)
assert np.allclose(T0, 2000 * np.pi, rtol=1e-12, atol=0)
assert np.allclose(g0, 2.0, rtol=1e-12, atol=0)

Here an assert stops with an error if its test is false. np.allclose compares numerical values allowing a small rounding difference. With atol=0 and the positive reference values used here, rtol=1e-12 permits a difference of one part in a trillion relative to the reference. This is a computational comparison tolerance, not the measurement precision of a physical constant. An appropriate tolerance for real observations would be a different question.

Example 5.13 · A test that can expose a wrong exponent

Suppose a faulty implementation uses mu / radius for field rather than mu / radius**2. At the benchmark it returns 4.0×106, while the independently calculated field is 2.0 m/s². A check that merely prints the returned value cannot reject it. A comparison with the hand value does. A unit audit also catches it: μ/r has units m²/s², not acceleration. Two different reasons support the diagnosis.

5.17 Design two controlled comparisons

Let k=r/r0 be a radius factor and q=μ/μ0 a source-strength factor. Dividing each formula by its reference value avoids large numbers and makes the controlled comparison visible:

vv0=qk,TT0=k3q,gg0=qk2.

Each ratio is dimensionless. The speed ratio contains one power of radius under a square root; the period ratio contains three. Those different powers encode two effects: a larger circle has a longer circumference and, for gravity alone, a lower allowed speed. If we change both source mass and radius, name both factors before claiming that one caused the result.

Example 5.14 · Two scenarios with the same period

Compare reference scenario A, (μ0,r0), with scenario B having eight times the source mass and twice the orbital radius, keeping G fixed. Then q=8 and k=2. Speed ratio is 8/2=2, period ratio is 23/8=1, and field ratio is 8/22=2. For our benchmark, B therefore has speed 4000 m/s, period 2000π s and field 4.0 m/s².

The unchanged period does not mean nothing changed. The satellite travels twice as far per revolution at twice the speed. These two scenarios are separate model systems; we have not described a manoeuvre that carries one satellite from A to B.

Allow 25 minutes. Before running any new code, make a table of v/v0, T/T0 and g/g0 for (a) q=1 with k=1,2,4, and (b) k=1 with q=1,4,9. Then propose a third scenario with both q≠1 and k≠1 that has the same speed as A. Does equal speed imply equal period? Show your reasoning.

Discussion of Activity 5.16

(a) Speed ratios are 1,1/2,1/2; period ratios 1,22,8; field ratios 1,1/4,1/16. (b) Speed ratios are 1,2,3; period ratios 1,1/2,1/3; field ratios 1,4,9. Equal speed requires q=k. Choosing both equal to 4 gives period ratio 64/4=4 and field ratio 4/16=1/4. Equal speeds do not imply equal circuit times when circumferences differ. Other positive choices q=k≠1 are valid if the exterior-source condition is retained.

The two requested comparisons can now be implemented without hiding which input varies:

factors = np.array([1.0, 2.0, 4.0])
v_r, T_r, g_r = circular_orbit(mu0, r0 * factors, R)
print("radius factors:", factors)
print("speed ratios:", v_r / v0)
print("period ratios:", T_r / T0)
print("field ratios:", g_r / g0)

for q in [1.0, 4.0, 9.0]:
    v, T, g = circular_orbit(q * mu0, r0, R)
    print("source factor:", q, "ratios:", v / v0, T / T0, g / g0)

The loop changes a scalar source parameter while radius stays at r0. Multiplying μ by q is equivalent to multiplying source mass by q because G is fixed. The hypothetical source radius R stays fixed too; this is a comparison of ideal models, not a claim that real planets can be resized or made denser without changing anything else.

5.18 Read the plots without changing the question

A curve can hide units, reference values and even what its horizontal axis represents. Here the axis will be radius factor k, not elapsed time. Every point on a curve is a different possible circular orbit. The plot does not show a satellite slowing down while it moves outward. That would be a different dynamical problem involving a changing orbit.

All three curves start at one because the reference case divided by itself is one. For k>1 with q=1, the speed and field curves fall while the period curve rises. Field falls faster than speed: at k=4, the factors are 1/16 and 1/2, respectively. Their different vertical scales in Figure 5.14 prevent the large period ratio from flattening the other relationships. Read the numbers on each axis before comparing slopes between panels.

k = np.linspace(1.0, 4.0, 121)
v, T, g = circular_orbit(mu0, r0 * k, R)
fig, axes = plt.subplots(1, 3, figsize=(10, 3.2))
for ax, values, label in zip(
        axes, [v / v0, T / T0, g / g0],
        ["speed / reference speed", "period / reference period",
         "field / reference field"]):
    ax.plot(k, values)
    ax.set_xlabel("radius / reference radius")
    ax.set_ylabel(label)
    ax.grid(True)
fig.tight_layout()
plt.show()

np.linspace makes 121 evenly spaced radius factors, including both endpoints. This makes a smooth-looking drawing of the algebraic model; it does not improve the physical model or create new observations. The loop pairs each returned quantity with its label. If you change one label without its data, the program can run without complaint while telling the reader the wrong story.

Allow 20 minutes. A report says, “The falling speed curve proves that satellites lose speed as they travel. The smooth curve confirms the orbit is circular.” Rewrite both claims. Discussion of Activity 5.17

The curve compares separate stipulated circular orbits at different radii; its horizontal axis is not time. Circularity is an input assumption, so the curve cannot prove it. To describe one changing trajectory we would need time-resolved positions or a justified dynamical model and initial conditions, beyond this algebraic comparison. Check axis quantities and units, correspondence of labels to data, source/reference values, and whether plotted points are predictions or observations. A smooth curve may only mean many points were evaluated.

5.19 Prediction, evidence and neglected effects

Three kinds of check now have distinct roles. A hand benchmark checks a result against reasoning outside the function. A scaling check tests relationships across inputs. An observation tests whether a model describes some part of the physical world. Agreement in the first two categories is necessary for trustworthy computation, but supplies no new observational evidence.

For a deliberately coarse astronomical comparison, NASA's Moon facts page gives an average Earth–Moon distance of about 384400 km and an orbital period of about 27 Earth days. Use the distance as a representative circular radius and the rounded Earth parameter 3.986×1014 m³/s². The model gives about 27.45 days. That is agreement at the broad scale of “roughly a month”; the source's whole-day summary does not support a precision test at the hundredth of a day.

There are also physical reasons not to expect the simplest model to be exact. The Moon's distance is not constant, Earth responds to the Moon's attraction, and the Sun also attracts both. The fixed, solitary source and exact-circle assumptions suppress those features. A discrepancy could combine imperfect inputs, a wrong implementation and model limitations; one number cannot tell us which. We should diagnose units and arithmetic first, then compare observations suited to the question, rather than tune an input until agreement appears.

Which month?

The interval between the same lunar phases is about 29 days in NASA's summary, whereas an orbit relative to the distant background is about 27 days. As Earth moves around the Sun, the illumination geometry takes extra time to repeat. These are different measured intervals. Comparing a model period with a phase cycle would mix definitions before any issue of numerical precision arises.

mu_earth = 3.986e14       # m^3/s^2, rounded
r_moon = 384400e3        # m, representative centre distance
R_earth = 6.371e6        # m, spherical approximation
v_moon, T_moon, g_moon = circular_orbit(mu_earth, r_moon, R_earth)
print("circular-model period / day:", T_moon / 86400)

Keep more digits during arithmetic than in the final physical conclusion. The computer may print many decimal places because it stores floating-point numbers; those digits do not remove rounding in the input data or the approximations just discussed.

Discussion and report criteria for Activity 5.18

A complete report identifies all SI inputs and the circular, exterior, dominant-source assumptions. Benchmark outputs are 2000 m/s, 2000π s and 2.0 m/s². B has μ=6.4×1013 m³/s² and r=4.0×106 m, giving 4000 m/s, the same period and 4.0 m/s². The two identities hold within floating-point rounding. An interior or surface radius must be rejected by this function's exterior contract. Radius comparisons reproduce Figure 5.14; the Moon estimate is about 27.45 days. A suitable observational next step is a documented series of Earth–Moon centre distances over a full orbit, with uncertainties and reference frame specified. The conclusion should not call the hypothetical arrays measured data or call numerical agreement proof that all neglected forces vanish. An openly documented mismatch is more scientifically useful than an unexplained changed input.

You now have a method for making a bounded computational claim: state the question, expose the assumptions and units, predict something independently, run and check, then qualify the conclusion.
