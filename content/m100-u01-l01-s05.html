A small notation change

A literal is a value written directly in code, such as 6 or 2.5. Use a decimal point, not a comma. For a negative value, type the keyboard hyphen-minus -, not the longer mathematical minus sign used in the page text.

  • Add and subtract with + and -.
  • Multiply with *, not × or the letter x.
  • Divide with /, not ÷.
  • Group with ( and ).

For these operations, Python follows the grouping and priority rules from Section 4. Spaces around an operator improve readability but do not change this calculation.

One expression, one output

First predict 3 × (2 + 4) − 5 by hand. Then type the following into a code cell:

3 * (2 + 4) - 5

Run the cell with its triangle button. Beneath it you should see:

13

In a Python notebook, the value of the cell’s final expression is normally displayed automatically. You do not need print here. Keep one expression per code cell for this activity. An output shown from an earlier run may be stale: editing the code is not the same as running it again.

Next try 8 / 4. The output is 2.0. Python’s / division produces a floating-point result; here 2.0 has the same numerical value as 2. Likewise, 2.5 + 1.5 gives 4.0. We will examine number types and decimal representation in Lesson 2. No new library is needed.

Four predict–type–run–explain cycles

For each cycle, write your prediction before running. Type the code yourself. Record what appeared and explain any mismatch. The template provides text cells for notes: double-click one to edit it, then use its check mark to render it. Paper notes are equally suitable; keep them with the notebook.

Thirty minutes of purposeful practice

  1. Signed subtraction: translate −3 − (−5) into Python. Predict the sign as well as the value.
  2. Equal priority: translate 18 ÷ 3 × 2. Compare it with 18 ÷ (3 × 2), using separate cells. Explain why the outputs differ.
  3. Decimal arithmetic: calculate 2.5 + 1.5 × 2. Predict which operation happens first.
  4. Your expression: write a single expression that starts with −4, adds 7, and then multiplies the entire result by 2. Decide where parentheses are needed. Do this one without opening the feedback first.
Compare after completing your predictions
  1. -3 - (-5) gives 2: subtracting −5 adds +5.
  2. 18 / 3 * 2 gives 12.0. 18 / (3 * 2) gives 3.0. The parentheses change what the division acts on.
  3. 2.5 + 1.5 * 2 gives 5.5: multiply 1.5 by 2, then add 2.5.
  4. (-4 + 7) * 2 gives 6. Without those parentheses, -4 + 7 * 2 gives 10 and fails the instruction to multiply the entire sum.

If your result differs, compare your typed expression character by character with your intended calculation. Correct your explanation as well as the code; keep the original prediction visible.

Repair a syntax error

Syntax is the grammar Python requires to read code. During the next ten minutes, type this deliberately incomplete expression into the repair cell and run it:

3 * (2 + 4

Python will report a SyntaxError, often with wording such as '(' was never closed. The wording and pointer location can vary with the Python version. Read the final error message, then inspect the expression. The marked location is a clue, not a guarantee that the original mistake is exactly there.

The intended calculation is “three times the sum of two and four”. Identify what is missing, predict the intended result, and make the smallest repair. Run the repaired cell and explain why your change preserves that intended calculation.

Check the repair

Close the group: 3 * (2 + 4) gives 18. Merely deleting the opening parenthesis would also remove the syntax error, but 3 * 2 + 4 gives 10, changing the meaning. Successful execution proves that Python could run this expression, not that it represents the problem you meant to solve.

Different errors need different questions

If you enter 6 / 0, Python can read the expression but cannot perform the division: it raises ZeroDivisionError. A missing parenthesis is a syntax problem; division by zero is an invalid arithmetic operation; a valid but wrongly grouped expression is a reasoning problem. You do not need to run this extra example. Use the distinction when diagnosing future work.
