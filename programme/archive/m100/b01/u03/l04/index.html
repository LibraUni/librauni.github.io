SECTION 1 · ABOUT 60 MINUTES

A calculation has conditions

A guard checks a condition before a calculation that requires it. Begin with the mathematical restriction: for 12/t, t must not be zero. The condition is a statement that is either true or false. The symbols < and > mean strictly less/greater; ≤ and ≥ include equality; ≠ means not equal. Mathematical validity is only one layer: if t represents a duration, your model may require t > 0. State which rule you are enforcing.

Worked example

For t = −2, the expression 12/t is mathematically defined, giving −6. If t is an elapsed duration in seconds, it is outside the physical model. The guard t > 0 protects that model more appropriately than t ≠ 0.

  2. time > 0 for a positive elapsed interval.

SECTION 2 · ABOUT 60 MINUTES

Trace the allowed and forbidden cases

A boundary value deserves its own test. A condition x > 3 rejects 3; x ≥ 3 accepts it. These two rules may differ at only one point, but that point can cause division by zero or violate a strict limit. Select a value below the boundary, at it, and above it before writing any code. For a single denominator restriction, test the excluded value and one permitted value on each side.

Worked example

For 8/(x − 3), try x = 2, 3, 4. The outputs are −8, undefined, 8. A guard x > 3 would reject the mathematically valid x = 2, so it is too restrictive unless the physical model additionally requires x > 3.

  3. reading ≤ 20.

SECTION 3 · ABOUT 90 MINUTES

Boolean comparisons and if/else

Python Boolean values are True and False. Comparisons use == for equality, != for inequality, and <, >, <=, >=. A single = assigns a value; it does not compare. An if line ends with a colon. The indented statements run only when its condition is true. An else line, also ending with a colon, selects the other branch. Use four spaces consistently. The protected calculation must be inside the valid branch, not before it.

Worked example

The code below computes a speed only for positive time. At time_s = 0 it prints the explanation and performs no division. The else branch prevents an invalid result rather than trying to repair one afterwards.

Type, predict, run

distance_m = 12
time_s = 3
if time_s > 0:
    speed_m_s = distance_m / time_s
    print(speed_m_s)
else:
    print("Duration must be positive")

SECTION 4 · ABOUT 60 MINUTES

Guard a sensor calculation

A calibration with y = (x − b)/a requires a non-zero scale factor. If a = 0, the model cannot recover y by division. Printing a helpful explanation is better than inventing a replacement number. Keep the model’s restrictions in the written account, not only in the program. A guard establishes that an operation is allowed; it does not show that the supplied calibration is accurate.

Worked example

For x = 11, b = 3 and a = 2, y = 4. With a = 0 the inverse formula is undefined. The original relation x = ay + b would instead say x = b, which might hold for many y or none; we will study such cases in U04.

Show intermediate steps and give units or restrictions where relevant. For code, record a prediction before running.

  2. What result follows from a = −2 with the other inputs unchanged?
  3. Does a != 0 establish that a sensor is calibrated correctly? Explain.
  4. Add a Markdown sentence stating the roles of x, a and b.
Feedback and worked answers
  1. 4.0 for a = 2; an explanatory message for a = 0 without division.
  2. −4.0; a negative scale is algebraically valid unless the model excludes it.
  3. No. It establishes a denominator restriction only; calibration needs supporting measurement evidence.
  4. x is the reading, a the scale parameter and b the offset.
