SECTION 1 · ABOUT 60 MINUTES

Three different kinds of claim

An identity is true for every permitted input, for example 2(x + 3) = 2x + 6. An equation asks which inputs make a statement true, for example 2x + 3 = 7. A numerical coincidence is agreement at a particular input without general equivalence. The domain matters: x/x = 1 is an identity only for x ≠ 0. One permitted counterexample disproves a universal claim; many agreeing examples do not prove it.

Worked example

x² = x is true at x = 0 and x = 1, but false at x = 2 because 4 ≠ 2. Two successful tests did not establish an identity. By contrast, distributing 3(x − 2) gives 3x − 6 for all real x.

Work it through

Show intermediate steps and give units or restrictions where relevant. For code, record a prediction before running.

  1. Classify 4(x + 1) = 4x + 4, 4x = 12 and x² = 4 as identities or equations.
  2. Give a counterexample to (x + 1)² = x² + 1.
  3. State the domain of (x − 2)/(x − 2) = 1.
  4. Explain why an excluded input cannot be used as a counterexample within a claim’s stated domain.
Feedback and worked answers
  1. The first is an identity; the others restrict the input and are equations.
  2. x = 1 gives 4 versus 2.
  3. All real x except 2.
  4. The claim was not made for that input; both validity and agreement must be checked.

SECTION 2 · ABOUT 60 MINUTES

Proof and counterexample do different jobs

To establish an identity, transform one side using valid algebraic laws until it matches the other, retaining restrictions. Avoid assuming the equality you are trying to establish. To reject a proposed identity, show one permitted input with unequal results. Choose inputs strategically: zero may erase the very terms that differ, so a non-zero value can be more informative.

Worked example

Claim: 2(x − 3) + x = 3x − 6. Expanding the left gives 2x − 6 + x = 3x − 6, proving it. Claim: (x + 2)² = x² + 4. At x = 1, 9 ≠ 5, disproving it.

Work it through

Show intermediate steps and give units or restrictions where relevant. For code, record a prediction before running.

  1. Prove 5(x + 2) − 2x = 3x + 10.
  2. Disprove 3(x − 1) = 3x − 1.
  3. Explain why x = 0 fails to expose the missing term in (x + 2)² = x² + 4.
  4. Prove (2x² + 6x)/(2x) = x + 3 on its stated domain.
Feedback and worked answers
  1. 5x + 10 − 2x = 3x + 10.
  2. At x = 0 the values are −3 and −1.
  3. The missing cross-term 4x vanishes at zero.
  4. Factor 2x(x + 3), cancel 2x for x ≠ 0.

SECTION 3 · ABOUT 60 MINUTES

Sampling does not prove an identity

Use code to explore a claim, while keeping the distinction between testing and proof explicit. Assign one input at a time and evaluate both expressions. The comparison == returns a Boolean. Here use small integers so arithmetic is exact. Floating-point equality is not a general test of numerical accuracy; we will return to that limitation later. Do not introduce a loop yet: make each chosen example intentional.

Worked example

The code tests the false claim x² = x at x = 2. It prints 4, 2 and False. Reassigning x = 1 and rerunning makes the comparison True without changing the status of the universal claim.

Type, predict, run

x = 2
left = x ** 2
right = x
print(left)
print(right)
print(left == right)

Work it through

Show intermediate steps and give units or restrictions where relevant. For code, record a prediction before running.

  1. Run at x = 0, 1 and 2, predicting first.
  2. Test (x + 2)² and x² + 4 at x = 0 and 3.
  3. Write an algebraic explanation of their difference.
  4. Save a conclusion that does not overstate the force of numerical testing.
Feedback and worked answers
  1. True, True and False.
  2. They agree at 0 (both 4) but differ at 3 (25 versus 13).
  3. The difference is 4x, from the two cross-products.
  4. For example: the counterexample disproves the identity; agreeing tests alone would not prove one.

SECTION 4 · ABOUT 60 MINUTES

Unit 3 synthesis

Retrieve the ideas without looking back first. A complete answer should state the claim, domain, method and conclusion. If you miss a task, identify whether the issue is distribution, cancellation, restriction, code syntax or the logic of evidence. Return to that specific lesson and attempt a fresh example. This is practice for a checkable mathematical argument, not a requirement to work quickly.

Worked example

For (x² − x)/x = x − 1, write x ≠ 0 first, factor x(x − 1), and cancel. A numerical check at x = 3 yields 2 in both forms. The factorisation establishes equivalence on the domain.

Work it through

Show intermediate steps and give units or restrictions where relevant. For code, record a prediction before running.

  1. Simplify 3(2x − 1) − (x + 4).
  2. Simplify (x² + 2x)/x with restriction.
  3. Disprove (a + b)² = a² + b² using non-zero a and b.
  4. Describe an appropriate guard for division by x − 2.
  5. Explain why three agreeing numerical cases do not establish an identity.
  6. Write a fresh identity and justify it by distribution.
Feedback and worked answers
  1. 5x − 7.
  2. x + 2, x ≠ 0.
  3. a = b = 1 gives 4 versus 2.
  4. Only divide when x != 2; otherwise explain the invalid input.
  5. A different permitted input may fail; a general algebraic argument is needed.
  6. For example 2(y + 4) = 2y + 8 follows by multiplying both terms by 2.
